## 1. Краткое описание проекта

### 1.1 Название проекта
Zeta

### 1.2 Суть проекта
Разработка и внедрение веб-системы и Telegram-бота для автоматизации парсинга Excel-расписания и централизованного учёта домашних заданий студентов ФКН. 

### 1.3 Бизнес-окружение проекта
Студенты факультета сталкиваются с проблемой потери информации о домашних заданиях, так как расписание ведется в неудобных Excel-таблицах на Яндекс.Диске, а ДЗ диктуются на парах или пишутся в разрозненных чатах. 
**Ожидания:** Продукт выведет учебный процесс на новый уровень прозрачности, снизит когнитивную нагрузку на студентов и старост, а также обеспечит единую точку правды по учебным активностям.

### 1.4 Цели проекта (SMART)
1. **К 22.11.2026 (конец итерации 3)** развернуть работающий MVP Zeta (парсинг Excel, веб-просмотр, deep-link авторизация через Telegram, CRUD ДЗ для старост). *Измеримо через чек-лист приёмки (п. 2.4).*
2. **В течение проекта (4 итерации по 2 недели, старт 12.10.2026)** довести продукт до объёма «LATER» (диалоговые сценарии бота, Telegram Mini App, задел под мобильное приложение).
3. **По каждой фазе Этапа 1 и каждой итерации Этапа 2** сдавать полный комплект проектных артефактов без просрочки (коэффициент срока = 1.0).

### 1.5 Риски проекта
* **Уровень совокупных рисков:** Средний.
* **Главные высокоуровневые риски:**
  1. *Технический:* Изменение структуры Excel-файла расписания на Яндекс.Диске со стороны деканата/преподавателей.
  2. *Ресурсный:* Нехватка реального фонда рабочего времени команды из-за параллельной учёбы и сессии.
  3. *Инфраструктурный:* Лимиты бесплатных тарифов LLM (GigaChat/OpenRouter) и хостинга.

## 2. Описание продукта и поставок

### 2.1 Продуктом проекта является (перечень поставок)
1. Backend на FastAPI (модули `auth`, `users`, `schedule`, `homework`, `llm`).
2. Веб-фронтенд на Next.js (авторизация, календарь/канбан, формы, админ-панель).
3. Telegram-бот (long polling) как техническая часть авторизации.
4. Схема БД PostgreSQL + миграции Alembic.
5. Unit- и e2e-тесты по каждому модулю.
6. Полный комплект проектных артефактов (документация, бэклог, журнал изменений, отчёты).

### 2.2 Главными требованиями к продукту являются
* **Функциональные:** Парсинг Excel с валидацией структуры; deep-link авторизация через Telegram с выдачей JWT; создание/редактирование ДЗ старостой с привязкой к паре; просмотр ДЗ студентом с фильтрацией по подгруппам; управление инвайт-ссылками; логирование действий.
* **Нефункциональные:** Отказоустойчивость на уровне базового веб-приложения; время отклика API < 2 сек; безопасность (JWT, ролевая модель).

### 2.3 Требованиями к продукту НЕ являются (исключения)
* Мобильное приложение React Native (только архитектурный задел).
* Telegram Mini App, LLM-валидация, кнопка-«звёздочка» (следующие итерации).
* Напоминания/push, комментарии, роль преподавателя, интеграции с внешними календарями.
* Обучение пользователей, пост-релизная поддержка, платный хостинг/юрлицо.

### 2.4 Правила приёмки поставок
Приёмка MVP и инкрементов осуществляется командой-заказчиком и куратором на основе следующего чек-листа:
- [ ] Парсинг Excel-расписания отрабатывает на реальном файле и сигнализирует об ошибке при несовпадении структуры.
- [ ] Пользователь проходит deep-link-авторизацию через Telegram-бота и получает JWT.
- [ ] Староста создаёт ДЗ через веб-форму, привязывая его к конкретной паре.
- [ ] Студент видит ДЗ своей подгруппы в веб-календаре и может переключиться на смежную.
- [ ] Инвайт-ссылки выдаются, отзываются и работают согласно иерархии ролей.
- [ ] Действия с ролями и ДЗ логируются (кто/когда).

### 3.2 Общий бюджет проекта
* **Финансовый бюджет:** 0 руб. (продукт бесплатный, внутренний, академический).
* **Трудозатраты (условный бюджет):**
  * Фонд времени: **3 часа в неделю на человека** (с учётом параллельной учёбы) → 15 чел.-ч/неделю на команду из 5 человек.
  * **Условная ставка:** 500 ₽/час на человека — базис для расчёта условной стоимости работ (сводная таблица оценок, Фаза 3, `06-сводная-таблица-оценок.md`).
  * ⚠️ Проверка реализуемости (PERT, `07-Сетевой-график-и-PERT.md` §6): при фонде 3 ч/нед суммарная трудоёмкость превышает доступный фонд — зафиксировано как риск сроков; решение (рост фонда или урезание скоупа) принимается на старте Этапа 2 и отражается в журнале изменений.

### 3.3 Ограничения по выполнению и организации работ
* Использование только бесплатных тарифов LLM и облачных хостингов.
* Жёсткая зависимость от доступности Telegram Bot API (long polling).
* Гибридная методология: предиктивное планирование на Этапе 1, адаптивная разработка (Scrum-подобные 2-недельные спринты) на Этапе 2.
