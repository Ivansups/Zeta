## 1. Метод оценки

- **Единица:** чел.-часы трудоёмкости. Дробление пакетов до задач на этом этапе не выполняется (см. Задание, Фаза 3).
- **Трёхточечная оценка:** O — оптимистичная, M — наиболее вероятная, P — пессимистичная. Ожидаемое значение `TE = (O + 4M + P) / 6`, дисперсия `σ² = ((P − O) / 6)²`.
- **Процедура:** каждый участник независимо оценил пакеты; расхождения обсуждены, итоговое значение — консенсус команды. Для типовых пакетов (CI, развёртывание БД) использована оценка по аналогии с поправкой на учебный контекст и бесплатные тарифы.
- **Предварительные эксперименты с инструментами:** оценки модулей `auth`, `schedule`, `homework` опираются на опыт команды со стеком FastAPI + SQLAlchemy + Alembic, Next.js (App Router) и long polling Telegram Bot API.
- **Стоимость в денежном выражении не оценивается:** проект внутренний, финансовый бюджет отсутствует; мера затрат — трудоёмкость в чел.-часах и сопоставление с фондом времени команды.

## 4. Буферы

- **Буфер на уровне пакетов не закладывался:** неопределённость уже отражена разбросом P − O; дублировать её в TE значит завышать план.
- **Календарный буфер проекта:** 11 рабочих дней (17.12–31.12.2026) между плановым завершением (16.12.2026) и дедлайном 31.12.2026 — см. [расписание](08-расписание-гант.md). Обоснование (σ критического пути) требует пересчёта PERT в `07` под обновлённый состав пакетов.
- **Риски** учитываются отдельно в реестре рисков, а не добавкой к оценкам.

## 5. Сопоставление с фондом времени

| Показатель | Значение |
|:---|:---:|
| Плановая трудоёмкость, ΣTE | 552.66 ч (реализация — 480.99 ч) |
| Номинальный фонд команды (5 × 3 ч/нед × 11,57 нед, 12.10–31.12.2026) | ≈ 174 ч |
| Превышение номинального фонда (реализация) | ≈ 307 ч |

Номинальные 3 ч/нед (устав §3.2) — средняя величина за весь период; в активные периоды пакетов загрузка исполнителя выше. Ритм проекта задаёт расписание [`08`](08-расписание-гант.md): на задачах ≈ 5,5–9,5 ч/нед на человека, вне пакетов исполнитель занят учёбой. Если фактическая загрузка не будет выше номинальной, скоуп режется по приоритету: сначала 7.4, 5.5, 6.3, 5.4 (пакеты с наибольшим резервом).
