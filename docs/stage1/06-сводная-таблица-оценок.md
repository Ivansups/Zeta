## 1. Метод и параметры оценки

### 1.1 Единицы измерения и формулы PERT
- **Единица трудоёмкости:** чел.-часы. В соответствии с требованиями Задания (Фаза 3), пакеты оцениваются целостно на 3-м уровне ИСР, дробление до задач на этом этапе не производится.
- **Трёхточечная оценка:**
  - $O$ — оптимистичная трудоёмкость;
  - $M$ — наиболее вероятная трудоёмкость;
  - $P$ — пессимистичная трудоёмкость;
  - Ожидаемая трудоёмкость: $TE = \frac{O + 4M + P}{6}$;
  - Дисперсия: $\sigma^2 = \left(\frac{P - O}{6}\right)^2$.

### 1.2 Методика оценивания и согласование расхождений
- **Процедура (модифицированный Planning Poker / Wideband Delphi):**
  - Ответственный за соответствующую зону (по ТЗ §10) готовил первичный диапазон оценок ($O, M, P$).
  - На общей сессии команды проводилась независимая калибровка: каждый участник давал свою оценку пакета.
  - При расхождении крайних оценок более чем на 30% исполнители с минимальной и максимальной оценками аргументировали свою позицию (обсуждались граничные риски, краевые кейсы API и возможные баги).
  - Итоговые значения $O, M, P$ утверждались общим консенсусом команды. Для типовых пакетов инфраструктуры и CI применялась оценка по аналогии с учебными проектами сходного стека.

### 1.3 Предварительные эксперименты с инструментами
Оценки технически рискованных модулей проверены на предварительных спайках (прототипах):
- **FastAPI + SQLAlchemy + Alembic:** проверена генерация миграций и асинхронные сессии к PostgreSQL.
- **Telegram Bot API (long polling):** подтверждена работоспособность глубоких ссылок (`deep-link` + поллинг) без необходимости поднимать публичный HTTPS-домен на этапе разработки (ТЗ §3.3).
- **Telegram WebApp SDK / Next.js:** проверена валидация подписи `initData` через HMAC-SHA256 (ТЗ §3.4).
- **LangChain + LLM (GigaChat / OpenRouter):** проверена латентность и структурированный парсинг текста ДЗ (ТЗ §7.1, §8).

## 4. Буферы проекта

1. **Буферы внутри пакетов (локальные резервы): не закладывались.**  
   Вся неопределённость и возможные риски технической реализации учтены в трёхточечной оценке через пессимистичные значения ($P$) и дисперсию ($\sigma^2$). Искусственное добавление процентов к $TE$ привело бы к искажению сетевого графика и нарушению методики PERT.
2. **Проектный календарный буфер: 11 рабочих дней (17.12.2026 – 31.12.2026).**  
   Интеграция MVP завершается 25.11, финализация баг-фиксов и подготовка приёмочных материалов запланированы на 16.12.2026. Оставшиеся 15 календарных (11 рабочих) дней до жесткого дедлайна (31.12.2026) выделены как общий буфер проекта на случай задержек приёмки и непредвиденных сбоев внешних API.
