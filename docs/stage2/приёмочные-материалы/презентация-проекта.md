# Слайд 2. Проблематика

### Исходная ситуация:
- Расписание факультета публикуется в Excel-таблицах на Яндекс.Диске, неудобных для просмотра со смартфона.
- Домашние задания фиксируются разрозненно: в беседах Telegram, личных переписках и тредах.
- Студенты путают дедлайны из-за смены числителя/знаменателя и различий между подгруппами.
- Старосты и старостаты тратят время на повторяющиеся вопросы одногруппников по текущим заданиям.

### Решение Zeta:
Единая платформа, привязывающая домашние задания к конкретным парам расписания с доступом через веб, мобильное приложение и Telegram.

# Слайд 3. Цели и рамки проекта

### Цели проекта (по Уставу):
1. **К 22.11.2026 (конец итерации 3):** развернуть рабочий MVP Zeta (парсер расписания, авторизация через Telegram Widget, веб-дашборд, CRUD домашних заданий, бот).
2. **В течение 4 двухнедельных итераций (12.10–15.12.2026):** реализовать полный стек клиентов (Next.js веб, React Native Expo мобильное приложение, aiogram бот, Telegram Mini App).
3. **Процессное качество:** сдача артефактов без срыва сроков, покрытие тестами и выполнение требований ТЗ.

### Модель самообслуживания групп (Community-Driven):
- Студент может самостоятельно создать группу в системе и стать старостой (`elder`).
- Ролевая модель: администратор (`admin`), староста (`elder`), помощник (`helper`), куратор (`curator`), студент (`student`).

# Слайд 5. Авторизация и безопасность

### Вход через Telegram:
- **Telegram Login Widget в вебе:**
  - Проверка HMAC-SHA256 подписи данных виджета токеном бота на стороне бэкенда:
    `secret_key = SHA256(bot_token)`
    `HMAC-SHA256(data_check_string, secret_key) == hash`
  - Защита от replay-атак через проверку времени `auth_date` (< 24 ч).
- **Telegram Mini App:**
  - Валидация строки `initData` по стандарту Telegram WebApp.
- **JWT сессии:**
  - Краткоживущий `access_token` (15 минут).
  - Ротация `refresh_token` (RTR) с обнаружением повторного использования (reuse detection): при попытке использовать старый токен аннулируются все активные сессии пользователя.

# Слайд 6. Интерфейс: веб-клиент

### Доска расписания (`/`):
- Просмотр занятий по дням недели с учётом числителя и знаменателя.
- Фильтрация подгрупп (1 и 2): общие пары группы плюс специализированные занятия подгруппы.
- Индикация наличия домашнего задания прямо в карточке пары.

### Доска домашних заданий (`/homework`):
- Режим таймлайна: группировка «Просрочено», «На сегодня», «На завтра», «Позже».
- Режим календарной недели: сетка Пн–Вс с переключением недель.
- Персональный чекбокс выполнения задания для студента.
- Форма добавления и редактирования ДЗ для старосты и помощников.

# Слайд 7. Администрирование и мобильное приложение

### Управление группой (`/admin`, `/settings`):
- Регистрация групп без участия общевузовского администратора.
- Генерация и отзыв инвайт-ссылок по ролям (студенты подгрупп 1/2, хелперы, кураторы).
- Назначение помощников старосты и передача роли старосты.
- Защита от смены групп (group hopping) и механизм безопасного выхода из группы.
- Тост-уведомления через `ToastProvider`.

### Мобильное приложение (React Native / Expo):
- Сборка под iOS и Android на базе Expo SDK 58.
- Просмотр расписания на день и неделю с фильтрацией подгрупп.
- Список домашних заданий с сохранением состояния.

# Слайд 8. Telegram-бот и Telegram Mini App

### Telegram-бот (`@zeta_hometask_bot`):
- Онбординг по команде `/start`.
- Поддержка deep-link ссылок вида `/start invite_<token>` для привязки к группе.
- FSM-сценарий создания черновика домашнего задания текстом.
- Ответы на вопросы студентов по домашним заданиям с ограничением частоты (throttling).

### Telegram Mini App (`/tg-app`):
- Запуск из меню Telegram без перехода в сторонний браузер.
- Автоматическая авторизация по `initData` пользователя.
- Полный интерфейс просмотра расписания и домашних заданий.

# Слайд 9. Процесс разработки и качество кода

### Практики разработки:
- Итеративная разработка: 4 спринта по 2 недели.
- TDD (Red -> Green -> Refactor): реализация создаётся под предварительно написанный падающий тест.
- Проверки репозитория перед коммитом:
  - `backend`: ruff lint, ruff format, mypy, pytest.
  - `frontend`: eslint, typecheck, jest.
  - `telegram-bot`: ruff lint, ruff format, mypy, pytest.
  - `packages/theme`: проверка синхронизации токенов (`scripts/generate.ts --check`).
- CI/CD в GitHub Actions:
  - Автоматический прогон тестов для затронутых пакетов.
  - Сканирование безопасности: gitleaks, Semgrep, Trivy, OSV-Scanner.
