## 1. Приёмо-сдаточный акт

### Состав приёмочной комиссии:
- **Со стороны Заказчика / Преподавателей:**
  - Представитель кафедры / ведущий преподаватель курса.
  - Представитель студенческого сообщества ФКН (заказчик продукта).
- **Со стороны Команды-исполнителя:**
  - **Иван Климов** — Руководитель проекта, ведущий бэкенд-разработчик.
  - **Данил Шелудько** — Ведущий фронтенд-разработчик.
  - **Алексей Берестнев** — Ведущий разработчик мобильного приложения.
  - **Даниил Ульянченко** — Разработчик Telegram-бота и Mini App.
  - **Никита Ремезов** — Разработчик мобильного приложения.

### Предмет приёмки:
Программный комплекс **Zeta** в составе:
1. Серверное ядро **FastAPI** с базой данных **PostgreSQL 17** и миграциями **Alembic**.
2. Веб-приложение на **Next.js 16** (App Router) и дизайн-токенами **`@zeta/theme`**.
3. Маршрут **Telegram Mini App** (`/tg-app`) с бесшовной авторизацией по `initData`.
4. Мобильное приложение на **React Native** (Expo SDK 58).
5. **Telegram-бот** на Python 3.13 / aiogram 3 с long polling.
6. Инфраструктура развёртывания **Docker Compose** и инструкции для прод-окружения **Coolify**.

## 2. Чек-лист соответствия требованиям Технического задания (Task.md v0.7)

### Раздел 1. Архитектура платформы и модульность (§1 Task.md)
| Требование | Критерий приёмки | Фактический результат | Статус |
|---|---|---|:---:|
| Открытая модульная платформа с независимыми клиентами | Бэкенд предоставляет единый REST API, клиенты не ходят в БД напрямую | Все клиенты (веб, мобилка, бот, Mini App) взаимодействуют только через HTTP API | ✅ Соответствует |
| Self-Service создание учебных групп | Любой студент может создать группу и автоматически стать её старостой | Реализовано в `POST /api/auth/groups` и в интерфейсе веба (`AdminPanel`) | ✅ Соответствует |
| Поддержка ролей взаимопомощи (Peer-to-Peer) | Наличие ролей старосты (`elder`), помощника (`helper`), куратора (`curator`), студента (`student`) | Роли зарегистрированы в перечислении `UserRole`, права валидируются декораторами | ✅ Соответствует |
| Гибкость расписания | Поддержка импорта/парсинга Excel и ручного занесения | Парсер Excel (`backend/schedule/parser.py`) + API ручного CRUD расписания | ✅ Соответствует |

### Раздел 2. Ролевая модель и матрица доступа RBAC (§2 Task.md)
| Требование | Критерий приёмки | Фактический результат | Статус |
|---|---|---|:---:|
| Суперпользователь (`admin`) | Доступ ко всем группам, пользователям и системным настройкам | Подтверждено тестами `test_admin_create_homework_for_any_group`, эндпоинты `/admin` | ✅ Соответствует |
| Староста (`elder`) | Создание/отзыв инвайт-ссылок, CRUD ДЗ и расписания, передача роли | Реализованы инвайты с подгруппами и ролями, передача старосты в `POST /api/auth/roles/transfer` | ✅ Соответствует |
| Помощник старосты (`helper`) | CRUD домашних заданий, корректировка расписания; запрет удаления группы | Реализован доступ в `backend/homework/router.py`, права подтверждены тестами | ✅ Соответствует |
| Куратор (`curator`) | Просмотр расписания/ДЗ, публикация материалов; запрет редактирования ДЗ старосты | Доступ на чтение подтверждён тестом `test_student_and_curator_cannot_create_homework` | ✅ Соответствует |
| Студент (`student`) | Просмотр расписания/ДЗ своей подгруппы, отметка «Выполнено», внесение ДЗ боту | Персональный чекбокс выполнения, FSM-черновик в боте отправляется на подтверждение | ✅ Соответствует |
| Защита от смены групп (Group hopping) | Пользователь, уже состоящий в группе, не может создать новую группу | `POST /api/auth/groups` возвращает `400 Bad Request`, тест `test_create_group_already_in_group_fails` | ✅ Соответствует |
| Корректный выход из группы (Leave group) | Студент может покинуть группу; староста не может уйти, если есть другие участники | Эндпоинт `POST /api/auth/groups/leave`, тесты `test_leave_group_*` | ✅ Соответствует |
