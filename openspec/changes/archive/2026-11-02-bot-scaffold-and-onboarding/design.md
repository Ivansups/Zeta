# Design

## Context

Пакет `telegram-bot/` представляет собой тонкий клиент к платформе Zeta в рамках монорепозитория. Пакет изолирован, использует Python 3.13, менеджер зависимостей `uv`, строгую типизацию (`mypy --strict`) и правила форматирования/линтинга `ruff` согласно `AGENTS.md`. См. `proposal.md` для описания целей и скоупа задач Z-08 и Z-09.

## Goals / Non-Goals

**Goals:**
- Чистая модульная архитектура пакета внутри `src/telegram_bot/`.
- Валидация конфигурации через переменные окружения (`BOT_TOKEN`, `BACKEND_BASE_URL`, `POLLING_TIMEOUT`, `WEB_APP_URL`, `LOG_LEVEL`).
- Устойчивый запуск long polling с поддержкой graceful shutdown (SIGINT/SIGTERM).
- Асинхронный HTTP-клиент к FastAPI backend (`BackendClient`) с обработкой таймаутов и сетевых сбоев.
- Роутеры и хэндлеры для онбординга: `/start` с кнопкой перехода в веб-приложение, `/help` и fallback для неизвестных команд.
- Полное покрытие unit-тестами с моками (без обращения к реальной сети Telegram или бэкенда).

**Non-Goals:**
- Бизнес-логика создания домашних заданий, FSM расписания и интеграция с LLM (вынесено в Итерацию 2: Z-10, Z-11).
- Прямой доступ к PostgreSQL или Redis (бот взаимодействует исключительно через REST API бэкенда).

## Decisions

### 1. Архитектура пакета `src/telegram_bot`
- `src/telegram_bot/config.py`: класс `Settings` на основе `pydantic-settings` для загрузки переменных из окружения / `.env` с валидацией обязательных полей.
- `src/telegram_bot/client.py`: класс `BackendClient` на основе `httpx.AsyncClient` для выполнения запросов к бэкенду Zeta (с методами проверки здоровья `healthcheck` и базовых операций).
- `src/telegram_bot/keyboards/onboarding.py`: разметка клавиатур, в частности Inline-кнопка перехода в веб-версию.
- `src/telegram_bot/handlers/onboarding.py`: `Router` с обработчиками `/start`, `/help` и fallback-хэндлером.
- `src/telegram_bot/main.py`: точка входа, конфигурация логгера, сборка `Dispatcher`, регистрация роутеров и запуск `dp.start_polling(bot)`.

### 2. Библиотеки и зависимости
- `aiogram>=3.15.0`: современный асинхронный фреймворк для Telegram Bot API с поддержкой роутеров и фильтров.
- `pydantic-settings>=2.6.0`: декларативное управление конфигурацией и типобезопасность.
- `httpx>=0.28.0`: современный асинхронный HTTP-клиент с поддержкой таймаутов и пула соединений.

### 3. TDD и стратегия тестирования
- Тестирование хэндлеров через вызов функций хэндлеров с фикстурами `Message` (с моком `bot.send_message` или `message.answer`).
- Тестирование конфигурации на корректную загрузку дефолтов и выброс ошибки при отсутствии `BOT_TOKEN`.
- Тестирование `BackendClient` с использованием `httpx.MockTransport` / `pytest_mock` без реальных I/O запросов.

## Risks / Trade-offs

- **[Сетевые сбои при long polling]** → aiogram автоматически осуществляет ретраи при сетевых ошибках; логирование на уровне `WARNING` информирует о временных проблемах без падения процесса.
- **[Отсутствие токена бота при локальной разработке]** → чёткое сообщение об ошибке с указанием скопировать `.env.example` в `.env` и указать токен.
- **[Поведение при SIGINT/SIGTERM]** → aiogram 3 `Dispatcher.start_polling` нативно перехватывает сигналы и корректно закрывает сессию бота. В `main.py` обеспечивается закрытие сессий `BackendClient`.
